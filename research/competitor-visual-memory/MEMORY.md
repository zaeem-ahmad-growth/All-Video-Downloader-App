# All Video Downloader competitor visual memory

## Scope and evidence

- **Date checked:** 21 September 2026
- **Listings:** 16 unique Google Play package IDs. The ASO Playbook contains all 16 as link annotations. The Feature Comparison identifies the same 16-listing audit but has no clickable Play links.
- **Deduplication:** the ASO Playbook repeats several links; all seven user-supplied links are already in its final unique set.
- **Asset source:** current public US English Play pages. Icons and the observed thumbnail references are linked in [index.html](index.html), without downloading or modifying competitor media.

## Visual asset inventory

| Finding | Evidence | Design implication |
| --- | --- | --- |
| Portrait storytelling dominates | 14 of 16 listings show only portrait screenshots in their current carousel. | Prioritize a strong portrait store-story first, then derive landscape/tablet assets from the approved composition. |
| Landscape is underused | Only InShot and AppTool-Browser-Video expose a landscape carousel visual. | A well-built landscape feature visual can differentiate, provided its hierarchy stays clear at small Play preview size. |
| Explicit public feature graphics are unavailable | Play listing pages show app icons and screenshots, but do not separately label the original feature graphic. | Treat any observed landscape screenshot as a reference only; do not call it a feature graphic without source evidence. |
| Category titles are repetitive | Most titles lead with “Video Downloader”, “All Video Downloader”, “Saver”, or “Player”. | Visuals must carry differentiation fast: lead with one verified capability and recognizable icon language. |
| Screenshot depth varies | Carousels range from 5 to 12 visuals. | Use fewer, distinct story beats rather than repeating the same UI state. |

## Competitive positioning from the supplied audit

The Feature Comparison describes the user's app as the only audited app combining a 9-tool editor, PIN/biometric vault, MP3 extraction, and background-resilient batch downloads. These are **document-provided audit claims**, not facts independently revalidated in this reference pass. The live-listing review supports a visual opportunity: competitors largely use portrait product walkthroughs, so a coherent sequence can make verified editor, vault, download management, and media-library benefits easier to understand.

### Recommended screenshot storyline for a future listing

1. **Download from link/browser** — show the core promise and a real supported flow.
2. **Choose quality and manage downloads** — show progress, pause/resume, and a clear outcome only if shipped.
3. **Save and organize media** — make the library result tangible.
4. **Edit video or extract audio** — one discrete edit result per screen.
5. **Private vault** — show security as an attached, connected popup from the media item.
6. **Status saver or other verified secondary feature** — keep the frame focused on the benefit.

Do not borrow competitor UI, photos, capacity promises, security claims, icons, or text. Use the reference library to study hierarchy, orientation coverage, and visual pacing only.
